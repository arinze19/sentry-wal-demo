Storage engine visualiser

Three ideas inside most databases: how an index finds a key, how an append-only log gets compacted, and how a write-ahead log survives a crash. Keys here are stock tickers.

Writes land in the memtable. When it holds 4 entries it flushes to an immutable sorted file (SSTable). Deletes write a tombstone. Reads check newest to oldest, so more files mean slower reads until compaction merges them.

Each change is appended to the log before it touches memory. After a crash, recovery loads the last snapshot and replays the log. Turn the WAL off, write some keys, then crash, and watch them disappear.
